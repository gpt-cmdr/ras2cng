**T19's guess was half right.** The peak was in `_join_raw_result`, but not because of the merge. Freestiler was never the peak before: 1.4-1.6 GB over the Python floor.

## What changed

`ras2cng/maplibre.py`, for freestiler Arrow input:

- **`_spill_dense_geometry`:** a mesh layer with results goes to disk in EPSG:4326 batch by batch, reading only its row groups. WKB and properties are separate IPC files. No shapely objects outlive a batch.
- **`_read_result_table`:** the variable's rows, without geometry; columns the delivery drops or that the row-group statistics show as all null are not read.
- **`_join_dense_result`:** `DataFrame.merge` on the keys alone gives row indices, so order and multiplicity are pandas' own. Each variable's spill holds properties only, and the tiler's load attaches the single geometry column.
- **`release_arrow_memory`:** returns the Arrow pool's free buffers between layers. Small: about 70 MiB on UPGU3.

The pandas `_join_raw_result` is unchanged except that a filtered read uses `_read_result_table`, so tippecanoe, GeoJSON and older freestiler gain from the read too. They still hold the mesh as a GeoDataFrame, and I did not measure their peak on the large models.

**Falls back to the pandas join:** `join_columns` on a mesh layer, a nested column with values, non-WKB geometry, stored pandas indexes or extension types, name collisions, an all-null key.

**Kept deliberately, because a tile must not change:** an integer column with a null anywhere in the plan file arrives as a double, because that is what pandas did to the whole file. `cell_last_iteration` is the live case. `_integers_with_nulls` reproduces it from the statistics.

## What still holds the peak

**freestiler's in-memory form of the largest layer.** On UPGU4 a face layer rises from 765 to about 2,250 MiB: about 320 MiB is the Arrow table (the pool's count) and about **1.1 GB is by subtraction Rust**, `Vec<Feature>` with `f64` coordinates and a `Vec<PropertyValue>` per feature, strings cloned per feature, roughly 500 bytes for each of 2.27 M faces.

The real fix belongs in the fork (columnar properties, compact coordinates, or tiling a batch at a time). **That is not small, so I opened no PR.** Taking the table out from under Rust would save at most the 320 MiB, and I did not attempt it.

## For you to decide

**Tiles carry three useless properties,** an old side effect of the merge suffixes: `mesh_name_result` (repeats `mesh_name`), `layer_result` (repeats the variable) and `hilbert_index_result`. Dropping them changes tile contents, so I left them. Experiment, one run each, `T20_DROP_JUNK` in the profiler, not in the PR:

| Model | `results-detail.pmtiles` | Peak MiB |
|---|---:|---:|
| UPGU4 | 1,196 MB -> 893 MB (-25%) | 2,281 -> 1,750 (-23%) |
| UPGU3 | 451 MB -> 343 MB (-24%) | about 840 -> 674 (-20%) |

Nothing in this repo was checked for reading them. I recommend removing them as a separate change.

## Fell short or left open

- **tippecanoe was not run.** Docker is down here, so I compared what it would be handed, not its tiles. Those inputs are byte-identical, and the viewer manifests of those runs were compared only as bytes.
- **The pandas fallback was not measured on UPGU3 or UPGU4.** Only identity was checked, on Davis (and tippecanoe inputs on Bald Eagle), and Python-path and 2.6 archives use the new join rather than the fallback, apart from sparse layers.
- **T12's Davis bug is still there, deliberately.** `index_column` joins on `cell_id` alone, so two meshes sharing IDs give 2,738 features for 2,716 cells, some with the other mesh's values. The new join reproduces it exactly, to keep tiles identical. It should be fixed on its own, and it **does change tiles**.
- **Scratch disk** should fall, with one WKB copy instead of one per variable, but I did not measure it.
- **Measurement slip, corrected:** the first benchmark series ran new code under the "base" label through a shell-quoting error in `PYTHONPATH`. I caught it when "base" peaked at 2.3 GB, discarded it (`T20\void\results_wrong_code.jsonl`), and every run now logs which code it loaded.
