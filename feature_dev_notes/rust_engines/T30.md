## Cause of the gap

I measured with freestiler 0.3.0.3 and ras2cng `master` (453f98e7) against tippecanoe 2.82.0 (T05's Linux build, run in Docker as T12 did, with ras2cng's own `_run_tippecanoe` flags). I decoded both archives tile by tile and split each layer into geometry, tags, IDs, keys and values, and framing. Feature IDs were off.

| Cause | Bald Eagle p07 (g04) | Davis | UPGU3 |
|---|---|---|---|
| **1. No tile deduplication in freestiler's PMTiles writer.** tippecanoe's route (mbtiles -> `pmtiles convert`) stores identical tiles once. Interior tiles of model extents, mesh-area perimeters and land cover are identical at z14-z17. | **The whole gap.** 3,461 tiles, 1,880 distinct; 333 KB | 0.8 KB | 1.72 MB of 2.32 MB |
| **2. Line simplification.** freestiler pre-simplifies lines with Visvalingam-Whyatt at about 8 px², which keeps 1.2-1.6 times tippecanoe's vertices on dense breaklines at z12-z17. tippecanoe uses Douglas-Peucker at 1 px. | none | small | about 430 KB (breaklines z12-17: 340,793 vs 218,703 vertices at z17) |
| **3. Value-table order.** tippecanoe sorts each layer's values by their encoded bytes and writes keys and values before features, so gzip finds longer matches. | 0.2% | 1.6% | 0.2% |
| **4. tippecanoe drops features that freestiler keeps.** | 8 breakline fragments | **2,243 `pipe_nodes` points over z0-z16** (1 of 133 at z0): the default `--drop-rate` 2.5 thins points. This is the whole remaining Davis gap. | 1,524 of 1,676 breaklines at z0 (the `keep_short_lines` stand-ins); land cover at z0-z1 (tiny-polygon reduction) |
| **5. Polygon tolerance.** ras2cng passes `polygon_simplify=0.5`; tippecanoe simplifies at about 1 px. | small | small | about 150 KB (`mannings_n_regions` z2-z14) |

The likely causes the brief named were checked:
- **Coordinate precision and buffer:** not causes. Both tilers use extent 4096 and buffer 5.
- **Properties repeated at low zoom:** the same in both tilers, except for the stand-ins in row 4.
- **Tile content otherwise:** geometry, tags, keys and values were equal or smaller in freestiler.
- **Raw data:** `G:\RustDev\work\T30\runs\*.bd.json`.

**Two findings for ras2cng itself (not fixed; ras2cng was not to be edited):**
- **ras2cng's tippecanoe path drops points.** `_run_tippecanoe` does not pass `--drop-rate=1`, so tippecanoe thins point layers below the maximum zoom (Davis pipe nodes). That breaks "Vector tiles never drop features". With `--drop-rate=1`, Davis is 1,134,156 bytes instead of 1,050,931.
- **Davis `Terrain_Profiles` is 70% of Davis `geometry.pmtiles`.** It is a numpy `repr` string (`"[array([ 0. , 51.48], dtype=float32)\n array(..."`) on every conduit at every zoom. Dropping that one column takes Davis from 1,129,401 to 343,964 bytes. It costs tippecanoe the same, so it is not part of the gap. It is a delivery-shaping issue: either keep it out of tiles, or deliver it as compact JSON.

## The fix in the fork (pure Rust, all opt-in)

| Option | Where | What it does |
|---|---|---|
| `deduplicate=True` | `freestile`, `freestile_layers`; `TileConfig::deduplicate` | Stores identical gzip payloads once and merges consecutive tile IDs into run-length entries, with the header counts and `clustered` flag that `pmtiles convert` writes. A hash hit is confirmed byte for byte against the spool. Every tile is still addressed and decompresses to the same bytes. |
| `sort_values=True` | `freestile`, `freestile_layers`; `TileConfig::sort_values` | MVT only. Writes each layer as name, keys, values (sorted by encoded bytes, as tippecanoe does), extent, version, then features. Decoded tiles are unchanged. |
| `line_simplify=<px>` | `FreestileLayer`, `freestile_layer`; `LayerData::line_simplify` | Per-zoom Douglas-Peucker on that layer's lines at `px` tile pixels, at every zoom including the maximum, in place of the VW pass. Each line is ranked once (`line_zoom.rs`), and a zoom keeps the vertices above its tolerance; a unit test proves this equals recursive DP. Endpoints are kept. A line that collapses falls back to its input vertices, as before. `keep_short_lines` still applies. Range (0, 64]. Polygons and points are untouched (byte-identical test). |

- **Defaults:** all off. Archives with the options off are **byte-identical to 0.3.0.3** on Davis, Bald Eagle and UPGU3, and the tests show the same.
- **Not available in:** `freestile_file`, the DuckDB streaming path, or categorical clustering.
- **CI change:** GitHub now refuses `macos-14` ("The configuration 'macos-14-arm64-us-default' is not supported"), so the macOS wheel and parity jobs were moved to `macos-15`, the same arm64 architecture. The PR has a separate commit for this.

## Size

Bytes of `geometry.pmtiles`.
- **Inputs:** the exact layers ras2cng 0.15 passes to the tiler, dumped from a real `ras2cng maplibre` run. The harness reproduces ras2cng's `geometry.pmtiles` byte for byte with 0.3.0.3.
- **Settings:** `buffer=5`, gzip 6, no IDs, ras2cng's `polygon_simplify=0.5` on polygon layers, and `keep_short_lines` on breaklines.

| Model | tippecanoe | 0.3.0.3 | New: dedup + sort + `line_simplify=1` | vs tippecanoe |
|---|---:|---:|---:|---:|
| Bald Eagle p07 | 972,376 | 1,300,546 (+33.7%) | **966,399** | **-0.6%** |
| Davis | 1,050,931 (drops 2,243 points) | 1,150,449 (+9.5%) | **1,129,401** | +7.5% |
| Davis vs complete tippecanoe (`--drop-rate=1`) | 1,134,156 | +1.4% | **1,129,401** | **-0.4%** |
| UPGU3 | 7,048,521 | 9,369,259 (+32.9%) | **7,248,146** | +2.8% |
| UPGU3, `polygon_simplify=1.0` | | | **7,092,381** | +0.6% (the breakline stand-ins tippecanoe drops) |
| UPGU3, polygon 1.0, short lines off (tippecanoe's completeness) | | | 7,013,882 | -0.5% |

**Per option on UPGU3:**
- `deduplicate`: 9,369,259 -> 7,662,907
- `+ sort_values`: 7,650,186
- `+ line_simplify=1`: 7,248,146
- `+ polygon 1.0`: 7,092,381

`line_simplify=0.5` gives 7,680,552, so 1.0 is the setting that matches tippecanoe.

**Reading this:**
- **Bald Eagle** is below tippecanoe.
- **Davis** is below a tippecanoe that keeps every point. Against ras2cng's current tippecanoe flags it is +7.5%, because those flags drop points.
- **UPGU3** with ras2cng's current `polygon_simplify=0.5` is +2.8%. With 1.0 the remainder is exactly the `keep_short_lines` stand-ins, which tippecanoe does not write.

So "at or below tippecanoe at equal completeness" holds on all three models. The two remaining differences are ras2cng choices: the polygon tolerance, and keeping every breakline.

## Positional error (`line_simplify=1`)

**Metric:** the maximum distance from every input vertex to the feature's decoded line work at that zoom, in tile pixels (1/4096 of a tile). The bound is 1 px of tolerance plus 0.71 px of grid snap.

| Layer | New, worst zoom | 0.3.0.3 (VW), worst zoom |
|---|---:|---:|
| UPGU3 breaklines | 1.64 | 4.96 |
| UPGU3 BC lines | 1.50 | 3.14 |
| UPGU3 reference lines | 1.34 | 1.63 |
| Bald Eagle structures | 1.39 | 2.82 |
| Bald Eagle BC lines | 1.10 | 0.80 |
| Davis conduits | 1.45 | 2.87 |

The new path is smaller **and** has a tighter worst-case error than the default VW path. In CSS pixels the worst case is 0.1 px.

## ras2cng change spec (for the integration agent)

All in `ras2cng/vector_tiles.py` unless noted. Every option is capability-detected, so PyPI freestiler and older fork builds keep today's behaviour.

1. **Capabilities.** Add to `freestiler_capabilities()`:
   - `"deduplicate": layered_ok and _accepts(layered, "deduplicate")`
   - `"sort_values": layered_ok and _accepts(layered, "sort_values")`
   - `"line_simplify": _accepts(getattr(module, "FreestileLayer", None), "line_simplify")`

   Add `deduplicate_available()`, `sort_values_available()` and `line_simplify_available()` helpers like `polygon_simplify_available()`.
2. **Archive options, every freestiler tileset.** In `run_freestiler`, on all three branches (Arrow, layered GeoDataFrame, single `freestile`), when the capability is present:
   - Set `kwargs["deduplicate"] = applied["deduplicate"] = True`.
   - Set `kwargs["sort_values"] = applied["sort_values"] = True`.
   - Both are lossless. Default on.
   - Knob `RAS2CNG_VECTOR_TILE_COMPACT=0` turns both off.
   - Measured on sparse tilesets only. Run the five-model viewer once to record `geometry-detail` and `results-detail` size and time before release. Expect ~0 for dedup on mesh tiles: T05 found 0 duplicate payloads.
3. **Per-zoom line simplification on sparse line layers.**
   - Constants:
     - `LINE_SIMPLIFY_ENV = "RAS2CNG_TILE_LINE_SIMPLIFY"`
     - `DEFAULT_TILE_LINE_SIMPLIFY_PX = 1.0`, which is tippecanoe parity. 0.5 gave 7,680,552 on UPGU3, still +9%.
     - Valid range (0, 64]; `0`/`off` disables.
   - In `simplify.py`, add `tile_line_pixels(kind)`, mirroring `tile_polygon_pixels`: return None for `not kind` or `kind in NEVER_SIMPLIFY` (`mesh_cells`, `mesh_faces`), else the setting.
   - Add `ArrowLayer.line_simplify: Optional[float] = None`, with the same `__post_init__` refusal as `polygon_simplify` on `NEVER_SIMPLIFY` kinds and unknown kinds.
   - In `_run_freestiler_arrow`, when `capabilities["line_simplify"]` and `source.line_simplify is not None`, set `options["line_simplify"] = source.line_simplify`.
   - **Where to set it** (`maplibre.py`):
     - `_write_delivery_source` -> `write_arrow_spill` (around line 546-570, where `tile_polygon_pixels(kind)` is computed): also pass `line_simplify=simplify.tile_line_pixels(kind)` for every geometry layer in `geometry.pmtiles`.
     - Results joined to sparse lines in `results.pmtiles` (`ArrowLayer(..., kind=geometry.kind)` near lines 2246 and 2491): set it for non-mesh kinds.
     - It is harmless on polygon and point layers (byte-identical in a test), so no geometry-type test is needed. Still pass it only for non-mesh kinds.
   - **Never** on `mesh_faces`, including results joined to faces (`kind == "mesh_faces"`). Faces' interior vertices are shared with the cell polygons.
   - `ras2cng pmtiles` (`pmtiles.py:213`) builds a layer with no kind, so it stays off there, as for `keep_short_lines`.
   - **CLI** on `maplibre` (and `maplibre-stored-vector` if it has line layers): `--tile-line-simplify PX` / `--no-tile-line-simplify`. `--no-simplify` should turn this off too, as it does the polygon filters.
4. **Keep:**
   - `keep_short_lines` on `mesh_faces` and `breaklines` (unchanged; verified complete with `line_simplify` on).
   - No `drop_rate`.
   - `buffer=5`.
   - Never `polygon_simplify` or `line_simplify` on mesh cells or faces.
5. **Polygon tolerance: a decision for the user, not a code change.**
   - Keeping `DEFAULT_TILE_POLYGON_SIMPLIFY_PX = 0.5` leaves UPGU3 +2.8% against tippecanoe.
   - 1.0 brings it to +0.6%, and the remainder is the breakline stand-ins.
   - T16/T19 chose 0.5 for less area bias at z8 (-4.8% vs -7.3% area on UPGU3 land cover).
   - Recommend leaving 0.5 unless "at or below tippecanoe" must hold on UPGU3-like models.
6. **Manifest:**
   - Add `vectorSimplification.lines = {enabled, tilePixels, method: "freestiler line_simplify (Douglas-Peucker per zoom)", layers}`, or the reason it did not run.
   - Add a top-level `vectorArchive = {deduplicate, sortValues}` from `applied`.
   - Per layer, `simplification.tileLinePixels`.
7. **Separate ras2cng fixes found here** (not part of this change):
   - Pass `--drop-rate=1` in `_run_tippecanoe`. It drops points today.
   - Stop delivering `Terrain_Profiles` as a numpy repr in tiles (70% of Davis `geometry.pmtiles`).
8. **Tests to add in ras2cng:**
   - capability detection with a fake module that lacks the new parameters;
   - `ArrowLayer` refusal of `line_simplify` on mesh kinds;
   - `_run_freestiler_arrow` passes `line_simplify` only for non-mesh kinds;
   - `run_freestiler` passes `deduplicate`/`sort_values` only when accepted;
   - one real-engine test (skipped without the capability) that `geometry.pmtiles` gets smaller and keeps every breakline at every zoom.
9. **Install line** after the release agent cuts it: freestiler 0.3.0.4 from the gpt-cmdr GitHub Release assets. Update `CLAUDE.md` (`vector_tiles.py` and `simplify.py` bullets, and the vector-tile conventions line that states "+34% / +9.5%").
