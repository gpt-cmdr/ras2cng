## What was added

There is a new `terrio::geoparquet` module (feature `parquet`) and a Python function, `terrio.write_geoparquet_layers`.

**Input.** The writer takes Arrow record batches with a WKB `Binary` geometry column. Column types are kept as they are: float32, list, struct, timestamp and Null. Data does not pass through terrio's `Layer` model.

**Options (`GeoParquetWriteOptions`).**
- ZSTD level, or Snappy, or uncompressed.
- `row_group_rows`.
- `layer_column` plus `layer_row_groups`: a row group also ends at every layer boundary.
- bbox covering:
  - the GeoParquet 1.1 `bbox` struct,
  - flat `bbox_*` columns (the pre-0.13 ras2cng layout),
  - or none.
- `order`: input, or Hilbert.
  - Hilbert is DuckDB `ST_Hilbert` of each bbox centre over the layer's extent.
  - Ties keep input order. Null and empty geometry go last.
- `hilbert_column`: stores the key as UInt64.
- `dictionary`: all columns, Utf8 only, or none.
- `statistics`:
  - page statistics, with a page index;
  - or chunk statistics, untruncated, with no page index and none on Null-typed columns.
- `geometry_statistics`.
- `crs` override. Otherwise the CRS comes from the GeoArrow field metadata, then from the input's `geo` metadata. With none, `crs` is written as `null`.

**Union schema.**
- Fields appear in first-appearance order.
- A field missing from a layer is null there.
- A Null-typed column unifies with a typed one.
- Per-layer `identity` columns must not hold nulls. They are non-nullable in the output when every layer has them non-nullable.
- Generated column names that collide with input columns are refused.

**`split_by_column`** splits one table on its layer column, in first-appearance order. The pieces are zero-copy slices.

**`GeoParquetWriteOptions::archive()`** (Python: `profile="archive"`) is ras2cng's profile:
- ZSTD 3
- `layer` column
- 65,536-row groups that end at layer boundaries
- `bbox` struct
- Hilbert order plus `hilbert_index`
- Utf8-only dictionaries
- chunk statistics

**File layout** matches fast-hdf's archive writer:
- root group `schema`;
- `ARROW:schema` written at close, carrying `geo`;
- `geoarrow.wkb` field metadata;
- list items named `element`.

## Reuse of fast-hdf's writer

The fast-hdf writer was ported, not depended on. It is bound to fast-hdf's HEC-RAS export contract:
- `ras:export:v1` CRS evidence;
- (Utf8, Int64) identity;
- finite floats;
- reserved names.

It also uses the `geoparquet` 0.9 crate on arrow/parquet 59, and terrio is on 58.

The following were carried over with the contract made generic: the Hilbert encoder, the union-schema plan, the per-batch `conform` step, and the writer properties (statistics, dictionaries, coerce types, root name, late `ARROW:schema`).

Column chunks are encoded in parallel, using terrio's existing `ArrowRowGroupWriterFactory` pattern.

## Equivalence (Bald Eagle p07, 16 archive files: 15 geometry + p07 results)

**How the inputs were produced.** I captured every frame `project._write_geoparquet` received during `archive_project(include_results=True, plans=["p07"])` with ras-commander 0.110.3 and fast-hdf 0.2.4. I wrote each frame three ways:
- ras2cng `engine="python"` (pyarrow);
- ras2cng `engine="native"` (fast-hdf);
- terrio: ras2cng's own table prep (`_arrow_table`, `_layer_identities`), then `write_geoparquet_layers(table, profile="archive", identity=...)`.

**What matched:**
- **16/16 files, terrio vs pyarrow and terrio vs fast-hdf:**
  - rows and order are identical (`pa.Table.equals`, `hilbert_index` included);
  - the Arrow schema is identical, field metadata and nullability included;
  - the `geo` metadata is equal as JSON;
  - row-group sizes are identical.
- **Hilbert:** on 200k random polygons with ties, terrio's order and stored keys are bit-identical to DuckDB `ST_Hilbert` and to ras2cng's NumPy port.

**No file is byte-identical.**

Against pyarrow, these differ:
- `created_by`;
- FileMetaData version 1.0 vs 2.6;
- the order of the key-value metadata and the formatting of the `geo` JSON;
- the `ARROW:schema` flatbuffer bytes;
- geometry statistics: pyarrow omits min/max for binary values over 4 KB, while terrio (like fast-hdf) writes them. `geometry_statistics=false` drops them entirely.

Against fast-hdf: no per-chunk difference in encodings, dictionaries, statistics presence, min/max or null counts. Sizes differ by -0.02% to +0.09%, from page boundaries and parquet-rs 58 vs 59.

## API notes for T10 (HEC-RAS driver writing ras2cng archives)

**Building the layers.** Build one `ArrowLayer` per catalog layer, in the order the archive should list them:

```rust
use terrio::geoparquet::*;
let layers = vec![
    ArrowLayer::new(Some("mesh_cells".into()), schema, batches).with_identity(["mesh_name", "cell_id"]),
    // ...
];
let mut opts = GeoParquetWriteOptions::archive();   // ZSTD 3, layer, bbox struct, Hilbert + hilbert_index
opts.crs = Some(projjson);                          // or put it in the geometry field's GeoArrow metadata
write_arrow_layers_to_path(layers, "Model.g01.parquet", &opts)?;
```

**Batches:**
- `batches` is any `IntoIterator<Item = terrio::Result<RecordBatch>>`, so a driver can stream. Hilbert order buffers one layer at a time; input order streams.
- The geometry must be WKB `Binary` named `opts.geometry_column` (default `geometry`). LargeBinary and native GeoArrow are refused.
- Every layer must share one CRS, or set `opts.crs`.

**Schema rules for ras2cng v2 parity:**
- ras2cng's Python frames carry the full union of columns in every layer, all nullable.
- The writer derives the same union itself from per-layer schemas. Fields that are non-nullable in every layer, or that are identity columns in every layer, become non-nullable.
- To match ras2cng exactly, give each layer the identity ras2cng's `KNOWN_IDENTITY` and `_layer_identity` would find. If any layer has no identity, nothing is required.
- Field types must agree across layers; only Null unifies. Column order is first appearance over the layers, then `layer`, `bbox`, `hilbert_index`.

**Report.** `GeoParquetWriteReport` returns `rows`, `layers`, `row_groups` and `bbox`, which is enough for the manifest's `geoparquet` record (engine `terrio`, `hilbert` `terrio`).

**Python.** `terrio.write_geoparquet_layers(table_with_layer_column, path, profile="archive", identity={...})` is a drop-in third engine for `ras2cng.geoparquet.write_geoparquet`. T11 can add it behind `RAS2CNG_GEOPARQUET_WRITER`. Capability-detect with `hasattr(terrio, "write_geoparquet_layers")`.

**Two behaviours to know:**
- The archive profile on a single table without a `layer` column is refused. Pass `layer_column=""` for single-layer files.
- With no CRS anywhere, `crs` is written as `null`. It is never defaulted to OGC:CRS84.

## Single implementation (follow-up, 2026-10-29)

The user rejected the first version, which ported fast-hdf's writer into terrio and left two
copies on different Arrow majors. There is now **one** implementation of the archive GeoParquet
writer: `terrio::geoparquet`.

### 1. Arrow versions aligned

- **terrio moved from arrow/parquet 58 to 59.** It is locked to fast-hdf's exact versions: arrow
  and parquet 59.0.0, arrow-buffer 59.3.1. That covers the workspace and the Python binding
  (`arrow-array` ffi).
- **wbvector's own GeoParquet (`wbvector/geoparquet`, parquet 58) is no longer enabled.** terrio's
  driver already read and wrote `.parquet`; only wbvector's format guess used it.
  - `VectorDriver::Parquet.to_wb()` now returns `None`.
  - A GeoParquet file without the `.parquet` extension is recognized by its `PAR1` signature with
    terrio's driver (new regression test `open_sniffs_geoparquet_without_its_extension`).
  - `cargo tree -i parquet` shows only parquet 59.0.0, used by terrio.
- **What the bump broke: nothing.** No source change was needed for the 59 API.

### 2. Consumers of fast-hdf's archive writer, and the option chosen

| Consumer | Use |
|---|---|
| ras2cng `ras2cng/geoparquet.py` | The **only** runtime consumer (`export_geoparquet_ipc_files`). |
| ras-commander (`G:\RustDev\src` checkouts, and released 0.110.3 in the venv) | None. Its `fast_hdf.export_arrow(format="parquet")` calls the *plain* `export_ipc_file(..., "parquet")` writer (Snappy, one layer), which is a different writer and is left in place. |
| fast-hdf | Its own unit tests (`geoparquet_tests.rs`, `archive_types_tests.rs`), `src/exports/README.md`, `docs/python-extension.md`, `docs/reference/extension-contract.md` and CHANGELOG. There is no CLI. `contract::wkb_bounds` was used only by the writer. |

**Option (a): retire the writer from fast-hdf.** Nothing forces (b):

- The only consumer, ras2cng, already depends on terrio (rasters, COGs, tiles).
- ras-commander does not use the archive writer at all.
- The future T10 path is terrio (format writer) depending on fast-hdf (engine), the opposite
  direction, so there is no dependency cycle.

**fast-hdf PR #53** removes the following:
- `geoparquet.rs`, `geoparquet_tests.rs`, `archive_types_tests.rs`
- the `export_geoparquet_ipc_files` binding
- `contract::wkb_bounds`
- the archive-profile docs, which now point to terrio

It is breaking for the Python extension (the function shipped in 0.2.4), so it **would ship in
0.3.0**. `API_VERSION` stays 11, because ras-commander never called the binding.
