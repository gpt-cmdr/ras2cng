## Result
`ras2fim-batch effective-terrain` (`rasmapper-effective-terrain/1`) rebuilds the grid of `RasTerrain.export_rasmapper_terrain(downsample_factor=1, rasterize_modifications=False)` from three inputs:
- the terrain's source TIFFs;
- the level-0 tile `Mask` of each source;
- the `Stitch TIN` from the terrain HDF.

`ras2fim-batch method` advertises it as `effective_terrain`. The output is a 256x256-tiled DEFLATE float32 GeoTIFF with nodata -9999, the same as the export, plus `report.json`.

### Rule
I derived the rule from exports only, by fitting hypotheses pixel by pixel. No vendor code was read.

1. **Stitch TIN first.** Linear interpolation in the containing triangle. Weights must be >= -1e-9, and later triangles win.
2. **Sources in priority order.** A source answers if all four pixel centres around the point (its "quad") are valid.
   - Once a higher-priority source has a valid pixel *containing* the point, the source also needs at least one quad centre in its footprint (mask bit 0).
   - Simpler variants each failed on at least one terrain: masks ignored, masks required on all corners, or ownership by the containing cell.
3. **Value.** The mean of the two diagonal triangulations of the quad, which is the same as four triangles around the quad centre.
   - It is **not bilinear**: bilinear reproduces 0.8% of values exactly, and 73% after rounding to 1/32.
   - Fractional offsets are binary32 and the arithmetic is binary64. With binary64 offsets, 412 Bald Eagle values are off by one 1/32 step.
4. **Rounding.** Binary32, then 1/32 with ties to even (.NET `Math.Round`). Every RAS terrain TIFF is already on that grid, because `CreateTerrain` quantizes inputs.
5. **Lattice.** The finest source (ties by priority) over the union of source extents, snapped outward. This is ras-commander's export lattice.

**Priority.** Taken from the `Priority` attribute when present. Older terrains such as Bald Eagle have none; there the terrain VRT order is used, highest first, as ras-commander's `_terrain_scope` already does.

## Terrain modifications: not implemented
- **High ground (TakeHigher, constant crest, written by `RasTerrainModWriter`).** The trapezoid model (projection to the nearest segment, crest, side slopes) matches 5,592 of 5,794 changed pixels, provided `Max Reach` is the **total** width (100 ft per side for 200). The model breaks at end caps (40 px) and polyline joints (48 px), plus about 30 px near a joint. Exact parity needs RAS Mapper's cap/joint geometry.
- **ras-commander writer bugs (likely), for the ras-commander owners.** RAS Mapper 7.0.1 did not honour two writer-created modifications:
  - `add_channel_modification`: the export was unchanged.
  - `add_modification_polygon(elevation_method="provided")`: the polygon was set to **0 ft** inside.
  - Treat writer-authored modifications as unqualified until this is checked.
