https://github.com/gpt-cmdr/ras2cng/pull/44. T24 wrote it as one commit, `13d089d1`, and left it as a draft with 3 of 6 checks red.

**Cause:** all three red checks were the Ubuntu jobs, and each failed the same test, `test_package_includes_terrain_modification_vectors`. The bug was in shipped code, not in the test:
- `maplibre.py` set the viewer's `provenance.sourceHdf` to `Path(source_hdf).name`.
- On POSIX, that returns a Windows path such as `H:\models\Terrain.hdf` unchanged.
- So a viewer packaged on Linux from a Windows-written archive carried the workstation path.

**Fix:** commit `5be0deb1`.
- New `maplibre._file_name()` uses `PureWindowsPath(...).name`, which splits on both separators.
- A unit test covers Windows paths, POSIX paths, bare names and `None`.
- No skips were added. The workflow is unchanged: Locked, Locked + fork wheels and Fresh install, on Ubuntu and Windows.
