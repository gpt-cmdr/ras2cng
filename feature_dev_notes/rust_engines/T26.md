### Was the bug confirmed?

**On the branch, yes. The report's premise, partly not.** The same reproduction (`zs_predictor_main.rs`, a Float32 COG with ZSTD or DEFLATE, through `write_raster` and `write_raster_dataset`) gave:

| build | `PREDICTOR=YES` | `3` | `2` |
|---|---|---|---|
| opengeos `main` a643093e | **2** | 3 | 2 |
| PR 1 branch before the fix | 2 | 3 | 2 |
| PR 1 branch after the fix (16203557) | **3** | 3 | 2 |

- **opengeos `main` also gives 2.** The "terrio `main` gives 3" in the report was `terrio-clb` main, which has its own `parse_predictor`. The PR did not regress upstream: upstream has always differed from GDAL here.
- **GDAL 3.12.2 (rasterio 1.5.2), tag 317:**
  - COG `YES`: 3 on Float32/Float64, 2 on Int16/Byte.
  - `STANDARD`: 2.
  - `FLOATING_POINT`: 3, and refused on integers.
  - GTiff `YES`: refused.
  - Script: `G:\RustDev\work\T26\gdal_pred.py`; output: `gdal_pred.txt`.

### Cause and fix

- **Cause.** `TiffOptions::from_write_options` parsed `PREDICTOR` as `"2" | "YES" => 2` for both drivers. It never looked at the data type.
- **Fix** (`crates/terrio/src/drivers/gtiff_write.rs`).
  - `parse_predictor(value, cog)` returns 0 ("by the data type") for a COG's `YES`, `ON` or `TRUE`.
  - `plan()` resolves 0 to 3 for Float32/Float64 and to 2 for other types.
  - `STANDARD` (2) and `FLOATING_POINT` (3) are accepted.
  - A GeoTIFF's `YES` stays 2, which is upstream's existing behaviour. GDAL refuses it, but refusing it here would break callers.
  - The refusal of 3 on integer data is unchanged.
  - CHANGELOG entry added.
- **Regression test:** `drivers::gtiff_write::tests::cog_predictor_yes_follows_the_data_type_as_gdal`.
  - Float `YES`/`on` give 3; integer `YES`/`TRUE` give 2.
  - `STANDARD` gives 2, `FLOATING_POINT` 3, explicit `2`/`3` themselves, and `NO` 1.
  - A GeoTIFF's `YES` gives 2.
  - An integer COG refuses `FLOATING_POINT`, `3` and `MAYBE`.
  - Pixels are read back bit for bit.
- **Scope.** The fix is folded into the single PR 1 commit, as asked. It has its own section in the PR body, which offers to split it out, because for upstream it is a behaviour change separate from area-matched overviews.
