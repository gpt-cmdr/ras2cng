## What changed

- **Arrow input:** with a capable build, `package_maplibre_viewer`, `package_maplibre_stored_vector` and `ras2cng pmtiles` write no NDGeoJSON. `RAS2CNG_FREESTILER_INPUT=auto|arrow|geojson` selects the input.
- **Reprojection:**
  - Mesh layers not joined to results, and the `ras2cng pmtiles` file, go in the model CRS and reproject in Rust.
  - On a CRS refusal, `run_freestiler` catches the `ValueError`, warns once, reprojects that CRS with pyproj, retries the tileset, and remembers the CRS for the process.
  - A layer with no CRS is refused.
- **Auto:** freestiler when the build has Arrow input and `buffer`, else tippecanoe when its CLIs are on PATH, else any freestiler. An older build keeps today's preference. `RAS2CNG_VECTOR_TILER=tippecanoe` still selects tippecanoe.
- **Never drops:** `buffer=5` is passed explicitly and `drop_rate` is never passed.
- **Properties:** `delivery_table()` keeps them as the GeoJSON path delivered them. It also drops all-null columns; consolidated archives carry a 178-column union schema, which is why each cell-result NDGeoJSON was about 880 MB.

## Gaps and things to decide

1. **Rust reprojection covers only part of the viewer.** Sparse layers, and mesh that is cached for a result join, are still reprojected with pyproj and travel as EPSG:4326 Arrow. With `--vector-results` that means no mesh layer uses the Rust path. Exact manifest bounds and the join need pyproj anyway, and even the Rust-path dense layers run pyproj over their vertices once for bounds. So routing the rest through Rust would add work without removing the Python pass. All of these routes skip GeoJSON.
2. **The default change needs an unreleased build.** `pyproject.toml` still has `freestiler>=0.3.0`, and PyPI 0.3.0 has no Arrow input. Until freestiler #5 ships in an installable build, installs keep today's behaviour.
3. **Default feature IDs cost 15-18% of Bald Eagle totals against IDs off.** This is what turns "smaller than tippecanoe" into "larger" on Bald Eagle. I left the default on because the task did not ask to change it. Recommend deciding whether the viewer default should go off.
4. **tippecanoe is a selection-time fallback only.** If freestiler raises during a run, the error propagates; there is no automatic retry on tippecanoe.
5. **Existing bug, not fixed:** `_join_raw_result` joins on `cell_id` alone. Davis has 2 meshes with 11 shared IDs, so 2,716 cells become 2,738 features, and those cells get a duplicate feature carrying the other mesh's values. Tiles from all paths inherit this. The likely fix is joining on `mesh_name` as well.
6. **Bald Eagle memory with results is still 3.4 GB.** It is about half of the GeoJSON path. I did not profile it; `_join_raw_result` reading the whole results parquet per variable is the likely cause.
7. **Not done:** browser or visual rendering check, the full 15-geometry archive, and more than two timing runs.
8. **`CLAUDE.md`, `RELEASE_NOTES.md` and the `vector_tiles.py` docstring cite this uncommitted file.** Commit it with the coordinator's notes.
9. **`T03/wheel_hdf5` has no `write_geoparquet_layers`,** while `T03/wheel59` does. Worth checking if the HDF5 reader branch was expected to include it.
