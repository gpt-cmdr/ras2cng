## Result in one paragraph

Both parts work. The Rust Final n Values raster is **bit-identical to RAS Mapper 7.0.1** on five geometries,
and the precipitation rasters are **pixel-identical to ras2cng's** on one real plan. **But the Rust raster does
not match what `terrain.export_mannings_raster()` writes today, and it should not.** Today's output is
ras-commander's `compute_final_mannings_raster()`, a deprecated alias of a self-described non-authoritative
estimate. It differs from RAS Mapper on 44-51% of common pixels. Switching changes users' output: see "Decision for T13".

### Why the estimate cannot match

| Geometry | Both valid | Values differ | Max difference |
|---|---|---|---|
| g01 | 43,126,123 | 50.67% | 0.115 |
| g09 | 96,745,731 | 44.29% | 0.115 |
| g11 | 96,624,956 | 44.05% | 0.115 |
| g13 | 43,126,123 | 50.67% | 0.115 |
| Weise_2D g08 | 0 (no overlap) | n/a | n/a |

Identified causes (I did not attribute the percentage to each cause):

1. **It ignores the calibration table's base n.** Bald Eagle Mixed Forest: land cover 0.12, table 0.08. The most common
   difference, -0.04, is this. The estimate reads the column name and skips it.
2. **Its grid differs.** It uses the TIFF's grid, about half a pixel off RAS Mapper's, clipped to the perimeter
   plus a 500-unit buffer (g01/g13 cover about 45% of the RAS Mapper grid).
3. **It has no 2D area default.** Pixels with no class stay no data rather than taking the area's n.
4. **Weise_2D, a model in metres at 0.01 cell size:** the fixed 500 buffer gives a raster at origin (-500, 501),
   which does not overlap the model at all.

## What T13 needs

**Requires:** fast-hdf #56 merged and released, ras-commander #786 merged. Both are additive and `API_VERSION` stays 11.
terrio: stock `GeoTiffWriter` is enough; no fork feature is needed.

### Decision for T13 (the user's call)

`ras2cng mannings` output will change: different values, and a different grid. Options: (a) switch the default to RAS Mapper's
rule and record the method; (b) keep the estimate as default and add an opt-in. I recommend (a), because the docstring of
`export_mannings_raster` already claims to replicate RAS Mapper's FinalNValueLayer and today it does not.
Refused geometries need a rule too: I suggest falling back to the estimate with a printed warning and recording
which method ran, never silently.

### Manning's wiring (`terrain.export_mannings_raster`)

- Check `HdfLandCover.rasmapper_final_mannings_available()`, then call
  `export_final_mannings_raster(geom_hdf, output_tif, ras_object=ras)`.
- It returns the path, not an array. The current code prints shape and range from an array, so read those from the file.
- Catch `ras_commander_fast_hdf.UnsupportedError` for the fallback. The caller's existing `geom_num = "01"` default still applies.
- `rasmapper_tile_corner=True` is the default. It reproduces a RAS Mapper quirk (last pixel of each 256 x 256 tile keeps the area default).
  `False` is the corrected value, not RAS Mapper parity.
- Output is plain tiled DEFLATE, not a COG. If a COG is wanted, go through `ras2cng.cog`.

### Precipitation wiring (`precipitation.export_precipitation_rasters`)

- Reference writer: `G:\RustDev\tmp\T09\qual\precip_one.py`, branch `native`. ras-commander has no wrapper; ras2cng calls fast-hdf directly.
- `fh.PrecipitationSteps(path, source=, indices=, units=)` iterates `(index, incremental, cumulative)`; `.info`, `.units`, `.indices`.
- Steps always come in **time order**. ras2cng's result lists follow the requested order, so re-sort results by `.indices`.
- Resolve timestamp tokens with the existing `_select_indices` over `.info["timestamps"]`, and pass integers.
- Tags and filenames stay in ras2cng. terrio takes `band_metadata=[{"description": label}]` (lowercase key) and
  `metadata=tags`. Pass `str(Path(hdf))` for `source_hdf`.
- `.units` is `None` for `native`: fall back to `.info["units"]`.
- terrio has no `overwrite`: keep the existing `FileExistsError` check.
- Keep the h5py + rasterio path as the fallback on any refusal, and for a non-float dataset, which is refused (ras2cng would coerce it).
- Update the `terrain.py` bullet of ras2cng's CLAUDE.md, which describes `export_mannings_raster()`.
