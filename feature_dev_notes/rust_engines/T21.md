## For ras2cng

- **Option:** `freestiler.FreestileLayer(input=..., crs=..., geometry_column=..., keep_short_lines=True)`, or `freestile_layer(..., keep_short_lines=True)`. `_LayeredTiler.add_arrow_layer(keep_short_lines=)` and `LayerData::keep_short_lines` underneath. Default off.
- **Capability check:** `"keep_short_lines" in inspect.signature(freestiler.FreestileLayer).parameters`.
- **Safe on `mesh_faces`:** lines already written do not change. No mesh guard is needed, unlike `polygon_simplify`.
- **`_run_freestiler_arrow` only builds a `FreestileLayer` for `ArrowLayer` sources.** A plain GeoDataFrame source there would not get the option. All layers in these five viewers came out complete, so they all took the Arrow path.

## What it writes

MVT 2.1 section 4.3.3.2: "For any pair of `(dX, dY)` the `dX` and `dY` MUST NOT both be `0`." Section 4.3.4.3 requires a `LineTo` with a count above 0 after each `MoveTo`. So a collapsed line cannot be written as itself.

**The choice:** a line that no tile of a zoom would contain is written once per zoom as a one-tile-unit segment.

- It goes in the tile holding its first vertex, never a neighbour's buffer, where a renderer would clip it away.
- It starts on the pixel that vertex snaps to.
- It runs one unit along the line's main axis, turning back if that would leave the tile, and along +x if the line has no direction.
- It carries the feature's properties and ID.

**Accuracy, measured against the archive** in tile units, on 25,829 stand-ins (UPGU3, UPGU4): true line to segment at most **0.705**, segment to true line at most **1.564**. The script failed on Spring's schema and I did not chase it, so Spring is not in that number.

**Fragments:** a line clipped across tiles gets no stand-in as long as any tile has it. The check runs the tile loop's own clip and snap, with a shortcut for a single line inside the clip rectangle of its home tile. The shortcut does not change output: all ten tilesets are byte-identical with and without it.

**Determinism:** whether a tile writes a feature does not depend on other tiles, so the result does not depend on the order threads look. Byte-identical at 1, 2 and 7 threads on the synthetic set in `tests/short_lines.rs`, and across repeated real runs (the ten tilesets above were built in separate processes).

## Each path that can lose a line

| Path | Finding |
|---|---|
| Tile-grid snap and MVT encoder | the defect; fixed by the option |
| VW pre-simplification | already falls back to the original line (T05); the stand-in covers what still collapses |
| Clipping | a fragment can collapse in one tile; the feature is present if another tile has it |
| Multi-part lines | **partly left.** A part that collapses is lost while another part survives, because adding it would change a feature already written. If every part collapses, the feature gets one stand-in. None of the five models has a multi-part line |
| Per-zoom `polygon_simplify` | polygons only: byte-identical with the option on or off on the synthetic set; every real polygon layer has no additions, with `polygon_simplify` on as ras2cng passes it |
| `drop_rate` | features dropped on purpose stay dropped |
| MLT | writes collapsed lines as zero-length vertices, so the option adds nothing (byte-identical test). **Read from the code; I did not decode MLT** |
| Off the Web Mercator map | no tile covers it, so it stays absent |
| `freestile_file`, streaming DuckDB | option not available there |

**Against base, decoded tile by tile, on all five viewers, 0 failures:**

- A tile with no addition is byte-identical after decompression.
- Every addition is one `MoveTo` and one `LineTo` of one unit, on or inside the tile, once per feature and zoom, only where the feature was absent.
- No tile was lost and no new tile appeared.

## Fell short

1. **tippecanoe-decode was not run.** Its binary is Linux. Docker's daemon is not running and WSL's Ubuntu fails to attach its disk (`ERROR_FILE_NOT_FOUND`); I did not touch either. The two independent decoders above stand in.
2. **Rendering in a browser was not checked,** so I have not seen how stand-ins look. At low zoom each is a dot the width of the line style, where there was nothing before, and 1,530 UPGU3 features land in the z0 tile. Worth a look before making it the ras2cng default.
3. **Multi-part lines can still lose a part,** as in the table above.
4. **MLT was not decoded.**
5. **Linux wheels were built by CI, not run here.** The R crate only gains the new field, and no CI job or local run compiles it.

## Decision for you

**Whether ras2cng turns it on for every line layer.** Mesh faces are free of size cost. Sparse layers with heavy properties pay at low zoom, up to +18.4% of `geometry.pmtiles` on Davis. If that matters, the choice to make when wiring it in is to raise those layers' minimum zoom or trim their tile properties; I did not change either.
