## Decisions implemented

1. **Storage areas are opt-in.**
   - fast-map 0.12 advertises `storage-area-level-pool/1`, which used to switch them on.
   - Now `fast_map._check_scope` refuses storage areas unless they are opted in, with the message "opt-in until it is faster than RAS Mapper (--fast-map-storage-areas or RAS2CNG_FAST_MAP_STORAGE_AREAS=1 …)".
   - Opt-in routes: CLI `--fast-map-storage-areas/--no-fast-map-storage-areas` on `map` and `map-hdf`; kwarg `generate_result_maps(fast_map_storage_areas=)`; env `RAS2CNG_FAST_MAP_STORAGE_AREAS`. The default is off (`STORAGE_AREAS_DEFAULT`).
   - `preflight()` stores `storage_areas_enabled` in the render. The product functions follow it, and fall back to the env var for direct callers.
   - Recorded in the manifests as `storage_areas_opt_in`.
   - New `MapResult.fast_map_skipped` (map type → reason) covers preflight, per-profile, velocity/derived qualification and engine-failure fallbacks.
2. **Derived products stay on by default.** Confirmed end to end (bridges, below).
3. **`ras2cng mannings` uses the Rust raster.**
   - `terrain.export_mannings_raster(method="auto")` calls `HdfLandCover.export_final_mannings_raster`.
   - On `ras_commander_fast_hdf.UnsupportedError`/`TopologyError`, or when the API or engine is missing, it falls back to `estimate_final_mannings_raster` (or the older `compute_final_mannings_raster`) with a printed WARNING. Other errors propagate, so a missing land-cover file fails loudly.
   - `--method auto|rasmapper|estimate`.
   - Provenance goes in the GeoTIFF tags `ras2cng_mannings_method` (`rasmapper-final-n` or `estimate`) and `ras2cng_mannings_fallback_reason`, and is printed. The summary is read block-wise.
   - The return type is unchanged (`Path`).
   - The CHANGELOG (RELEASE_NOTES) and the docs state the 44-51% behaviour change.
4. **Feature IDs are off by default.**
   - `vector_tiles.FEATURE_IDS_DEFAULT = False`. `--feature-ids` / `RAS2CNG_VECTOR_TILE_IDS=1` opts in.
   - Updated: the docstring, CLI help, the maplibre/pmtiles guides, and CLAUDE.md (T12: -10.0% / +2.8% vs tippecanoe without IDs; the sparse `geometry.pmtiles` caveat is kept). Tests updated.
5. **User-supplied terrain CRS for Rust boundaries.**
   - `--fast-map-terrain-crs-hash` (`fast_map_terrain_crs_fnv1a64`) is validated as 16 hex digits (`normalize_crs_fnv1a64`), then passed to `RasFim.map_inundation_boundaries(terrain_crs_fnv1a64=)`. That keyword is capability-checked; without it the run refuses.
   - It applies to the boundary terrain only, and is recorded as `ras2cng.terrain_crs_fnv1a64` in the boundary manifest.
   - Without the hash, a CRS identity refusal now appends `terrain_crs_hint()`. That runs `ras2fim-batch terrain-info` and prints the engine's `crs_wkt_fnv1a64`, the start of its WKT and the exact flag. The value is shown, never used.
   - ras-commander checks it: the engine's hash must match, and it is used only when the engine has no EPSG code.
6. **Unmodified terrains only.** Kept (`13ca5185`).

The repo's convention: annotated tag `vX.Y.Z` ("ras2cng vX.Y.Z") on the release merge commit, a GitHub Release, and PyPI via `uv build` + `twine upload`. There is no publish workflow, and 0.12.0 was uploaded without a tag or GitHub Release.

1. **Wait for the terrio fork release** `gpt-cmdr-v0.5.0.1` (R2: re-enable Actions on gpt-cmdr/terrio, then follow R2's *To finish*). Then check that the `--find-links` URL in the docs resolves.

   - `uv build` in a clean checkout;
   - check the wheel's metadata: `Requires-Dist: ras-commander[full]>=0.113.0`, no direct URLs;
   - `twine upload dist/ras2cng-0.13.0*`;
   - `git tag -a v0.13.0 -m "ras2cng v0.13.0"` and push the tag;
   - `gh release create v0.13.0` with the 0.13.0 notes.
3. **Optional:** tag the historical 0.12.0 (`ae81d982`, the #23 merge `91aa9d2b`) if a GitHub Release is wanted for it.
