## 2. Velocity default-on readiness

- **The 826 / 1,196 bridges p05 mask difference was a reference artifact.** The
  "sloping" reference `C\corpus\ref\bridges\max_sloping\Velocity (Max)` is a
  byte-identical copy of the horizontal-mode velocity (same size, written 19 min after
  the depth). A genuine native sloping run (`ref\bridges\slo_max`) has velocity mask =
  sloping depth mask, and fast-map matches it: 973,902 px, 0 value and 0 mask
  differences (published 0.11.0 and this branch).
- Rule, verified on bridges Max (horizontal, sloping, slopingPretty) and t216: RAS
  Mapper's velocity **values do not depend on the render mode**; it clips them with the
  **active mode's depth** (`depth > 0`). Shear stress behaves the same.
- Horizontal: new `velocity_depth="horizontal"`. Needs RAS Mapper's horizontal dry-cell
  gate `wse > cell minimum + 0.001` (float32) before the plot test (without it: 1,845
  extra pixels).
- slopingPretty: velocity values identical on every common pixel; the mask follows
  fast-map's slopingPretty depth, which on this bridges Max reference differs from native
  (75 native-only / 28 extra pixels, 284 depth values), with and without the native
  `PostProcessing.hdf` corners. That is a slopingPretty depth gap, not a velocity gap.
- Recommendation for T13: velocity can be default-on for sloping and horizontal on
  engines advertising `velocity_depth`. Keep slopingPretty velocity opt-in until
  slopingPretty depth is re-qualified on bridges.

## 3. Duration: qualified

- RAS Mapper's recession (`ArrivalTimeRenderer.ParseWindowBackward`): each cell's WSE
  series is split into monotone windows at its local extrema (PostProcessing "Increasing
  Regions": `v[k] >= v[k-1]` is rising), searched from the last window. With `L` the last
  wet time the recession is `L` when it ends a window, is one step before a falling
  window's end, or starts that falling window (the round-half-even bisection gives up and
  the previous window's end is written); otherwise `L + 1`. A first-window give-up
  writes no recession (duration NoData).
- Python emulation first: Davis 4,879/4,879 and bridges 959,043/959,043 (old rule 103 and
  11 off). Then in Rust, end to end: arrival, duration and percent all **0 differences**
  on both (bridges 29 s, Davis 4.5 s for all three products).
- Engine method ID kept at `/1` (released ras-commander checks it); capability
  `duration_rule: rasmapper-backward-window-recession/1`. Memory: 8 bytes per cell
  extremum, admitted against the budget (worst case capped at half of it).

## 4. Froude, D x V, D x V², shear, Max derived

- D x V `d*v`, D x V² `(d*v)*v` in binary32. Froude: RAS Mapper computes `g*d` in
  **binary32** and divides in binary64 (`DepthAndVelocityRenderer`); the old helper did
  `g*d` in binary64 (the 1-ulp residual). Fixed; gravity is the float32 `SharedData`
  constant (32.174 US, 9.80665 SI), from the plan's `Units System`.
- Max derived (`DepthAndVelocityRenderer.GetDVComputer`): per output time the product of
  that time's rendered depth and velocity, then pixelwise max; the valid area is the
  union (bridges 973,956 > the 973,902 depth mask). Engine `reduce_max` does this in one
  pass without writing per-time rasters.
- Shear stress (not implemented): `MeshFV2D.ComputeFaceTrueShear`, per face
  `tau = k * |V| * V * n^2 / R^(1/3)` with `k` = 28.258362 (US, 62.4/1.486²) or 9810 (SI),
  `n` from `ReadFaceMannValues`, `R` the PostProcessing face hydraulic radius at that
  profile. The face vectors come from `ComputeSlopingFacepointVelocities_LeastSquares` +
  `ComputeFaceTrueVelocities` (not the C-stencil reconstruction velocity maps use), are
  averaged to facepoints and interpolated like velocity. Max uses PostProcessing
  `Maximum Shear` face scalars. Implementing it needs the face hydraulic-radius
  post-processing and that second reconstruction. Native shear values are also
  render-mode independent.
