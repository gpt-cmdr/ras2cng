## 1. terrio-clb: `-wm` port

**PR:** https://github.com/CLB-Engineering-Corporation/terrio-clb/pull/16, branch `t31/warp-wm`, head `6b3b16ab`.
**Merged** into `main` as `635f51f4f7f51e8b564129562a47f1cf99f64a90`. Main had not moved since the branch point (`ccc4ce03`), so no rebase was needed. The T27 HECRAS area was not touched.

What the port found:

- terrio-clb **already had** the path-to-path Python warp and mosaic from #13 and #24:
  - `warp(paths, dst=, max_memory_mib=)` goes through `warp_to_path` (chunks read by window, rows streamed);
  - `mosaic(paths, dst)` goes through `mosaic_to_path`.
- So the upstream branch's Python streaming half was already there. What was missing:
  - **`parse_warp_memory`** / `warp_memory_from_number` / `DEFAULT_MEMORY_LIMIT` in `ops::warp`. This is GDAL 3.13.3's `CPLParseMemorySize()` plus gdalwarp's `-wm` handler: megabytes below 10000, bytes from 10000, `K`/`M`/`G`[`B`] units, and 0 keeps 64 MB.
  - **`terrio warp --wm`.** `docs/cli.md` already documented `--wm`, but the CLI had no such flag.
  - **Python `wm=`.** It accepts a number or a string, like gdalwarp's `-wm`, and is added **beside** `max_memory_mib`.
  - **JavaScript `wm`.** A number below 10000 is now megabytes; it used to be bytes, as upstream changed it too.
- **ras2cng needs no change:** `max_memory_mib` is kept and still appears in `__text_signature__`. `wm` and `max_memory_mib` cannot be given together; doing so raises.
- **Docstring corrected.** The `max_memory_mib` docstring said "the values do not depend on it". That is false for interpolating kernels, exactly as with gdalwarp (measured below).
- **Deviation from upstream:** `%` is refused here, because terrio-clb has no `usable_memory`. Upstream reads it from Linux `/proc`.
- **Without the option, behaviour is byte-identical.** ras2cng depth tiles from this build are byte-identical to the 0.5.0.3 release wheel's.

  - real-data `test_warp_memory_is_gdalwarps_wm` against `gdal.Warp -wm` 64MB/0/4/1/500000;

**What T13's discrepancy was.** It was not a chunking bug. It has three separate causes, largest first:

1. **Overview selection (the 151 ft).**
   - terrio's default `overview="AUTO"` is gdalwarp's `-ovr AUTO`. At 40 ft it read the 20 ft source's internal 2x overview.
   - `_merge_tifs` (rasterio `reproject`) reads full resolution.
   - This accounts for 987k pixels, up to 151 ft, on the cliffs. `overview="NONE"` removes all of it.
2. **`_merge_tifs`'s own 512-px block warps (up to 4.44 ft).**
   - Each block is a separate GDAL warp with its own source window and kernel scale.
   - GDAL's own whole-output warp differs from `_merge_tifs` by exactly the same 18.5 M pixels as terrio does.
   - So this is a property of `_merge_tifs`, not of terrio.
3. **Chunk size (up to 0.014 ft).** T13's `max_memory_mib=512` against the 64 MB default changes 25.2 M pixels by at most 0.014 ft. This is the same effect as `gdalwarp -wm`.

**Does this version match?** Yes:

- At the same `wm` with `overview="NONE"`, terrio is **bit-identical to GDAL** and **bit-identical between path and memory**.
- The memory gain T13 did not see came from its 512 MiB choice: 948 MiB at 512 MiB, against 452 MiB at the default and 346 MiB at `wm=16`.

## 3. Defect found (not fixed: outside this task's write scope)

**`mapping._reproject_tifs` never reprojects.**

- It imports `calculate_default_transform` from `rasterio.transform`. That module does not have it: it lives in `rasterio.warp`.
- The resulting `ImportError` is caught. The function prints "rasterio not available for reprojection" and returns the original TIFFs.
- So `ras2cng map --reproject-wgs84` silently delivers the native CRS.
- Confirmed with rasterio 1.5.2. The test in `tests/test_cli.py` mocks this function, so the test suite does not see the bug.

## 4. Spec for the integration agent

**Adopt: yes, for reprojection. Optional, with a user decision, for `_merge_tifs`. Tiles need no change.** Requires terrio-clb at or after `635f51f4`, or any CLB build with #13 (0.5.0.1+) for the `max_memory_mib` path. `wm` is only needed to pass a gdalwarp-style string.

### 4.1 Raster tiles: no code change

- Keep `streaming_warp_supported()` detecting `max_memory_mib`. Keep `RAS2CNG_TERRIO_MAX_MEMORY_MIB` unset by default.
- Fix the `pmtiles.md` sentence noted in 2b.

### 4.2 `terrain._reproject_to_match` and `mapping._reproject_tifs`: terrio path-to-path, rasterio fallback

Add one shared helper, for example `ras2cng/raster_tiles.py` or a new `ras2cng/warp.py`:

```python
def reproject_path(src: Path, dst: Path, dst_crs, *, resampling: str = "bilinear") -> Path:
    """Path-to-path reprojection, GDAL's grid and values (bilinear within float rounding)."""
    if raster_tiles.streaming_warp_supported():          # terrio warp(..., max_memory_mib)
        import terrio
        memory = raster_tiles.max_memory_mib()
        terrio.warp(
            str(src), dst=str(dst), t_srs=CRS.from_user_input(dst_crs).to_wkt(),
            resampling=resampling, overview="NONE",       # never read source overviews (2a)
            **({"max_memory_mib": memory} if memory else {}),
        )
        return dst
    return _reproject_rasterio(src, dst, dst_crs, resampling=resampling)  # today's code
```

Notes:

- **Keep the nodata defaults.** terrio's default `dstnodata` is the source's, as `_reproject_to_match`'s copied `meta` is. Data type and band count are kept.
- **Pass `overview="NONE"`.** terrio defaults to gdalwarp's `-ovr AUTO`, while rasterio reads full resolution. This does not matter at native resolution, but it is the 151 ft trap of 2a when downsampling.
- **Do not pass `tap` or `tr`.** The default grid already equals `calculate_default_transform` (verified, `same_grid: true`).
- **`_reproject_to_match(src_dataset, ...)`** takes an open rasterio dataset. Pass `src_dataset.name` as the path.
- **`_reproject_tifs`:** first fix the import to `from rasterio.warp import calculate_default_transform, reproject, Resampling` (section 3), then route through the helper.
- **Expected effect:** reprojection 3.9x faster on Terrain50 (7.8 s vs 30.3 s), with reprojection peak -39% (1,033 vs 1,682 MiB). Values change by at most 2.4e-4 ft on 876 of 182 M pixels (float rounding), with the same grid and mask.
- **Tests:**
  - helper uses terrio when available, passes `overview="NONE"`, honours the memory env;
  - rasterio fallback when `streaming_warp_supported()` is False;
  - a small real-raster equivalence test against rasterio, with `atol=1e-3` and an equal mask;
  - a regression test that `_reproject_tifs` actually changes the CRS.

### 4.3 `terrain._merge_tifs`: terrio multi-source warp (behaviour change; ask the user)

```python
if raster_tiles.streaming_warp_supported():
    import terrio
    terrio.warp(
        [str(p) for p in reversed(valid_tifs)],        # gdalwarp painter: priority 1 drawn last
        dst=str(output_tif), t_srs=ref_crs.to_wkt(),
        te=(left, bottom, right, top), tr=(resolution, resolution),
        resampling="bilinear", overview="NONE", dstnodata=float("nan"), ot="float32",
        compress="DEFLATE", tile_size=block_size, bigtiff=True,
        **({"max_memory_mib": memory} if memory else {}),
    )
    # then the same build_overviews(...) block on the output (rasterio "r+")
```

- **Measured:** 4.9 s vs 20.9 s, and 453 vs 829 MiB peak. `wm=16` gives 346 MiB.
- **Equivalence:**
  - Bit-identical to GDAL's own whole-output painter warp.
  - **Not** identical to today's `_merge_tifs`: 18.5 M of 49.7 M pixels differ, max 4.44 ft, 274 over 1 ft, with identical masks.
  - The current blockwise output is the outlier, not terrio.
- **Leave the default off until the user approves.** Use a `RAS2CNG_TERRAIN_MERGE_ENGINE=auto|terrio|rasterio` switch, and record the engine used in the terrain manifest.
- **Do not omit `overview="NONE"`.**
- **Write options.** terrio's writer takes `compress`/`tile_size` here; DEFLATE without predictor 3 makes this intermediate somewhat larger. The published terrain COG is rebuilt by `ras2cng.cog` anyway.

### 4.4 Defaults

- **Chunk memory:** keep terrio's 64 MB default. Do not pass `max_memory_mib`/`wm` unless `RAS2CNG_TERRIO_MAX_MEMORY_MIB` is set.
- **Smaller values** cut the warp's peak (16 MiB: -40 to -50%). They also change interpolated pixels, as `gdalwarp -wm` does, and they do not lower the COG writer's ~1.9 GB peak on Terrain50.
