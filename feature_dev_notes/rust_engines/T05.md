## Where the bytes went (`feature_dev_notes`-style attribution, `G:\RustDev\work\T05\bench\bytes.py`)

- **Per-feature encoding was already equal.** At z15, raw MVT bytes per feature are 48.3 for freestiler and 48.5 for tippecanoe. Tags (0.98 MB) and keys+values (1.65 MB) cost the same.
- **The whole gap was feature count, from the clip buffer.** freestiler's 5% buffer is 204.8 tile units; tippecanoe's default `-b 5` is 80. The wider buffer repeated 10-12% more features per zoom (z15: 111,617 vs 100,025) across 268 vs 262 tiles. With `buffer=5`: 100,045 features at z15, 90,425 vs 90,402 at z10, and 262 tiles, which is tippecanoe's tile count.
- **Not levers:** duplicate points (0 for both), collinear points (32-364 per zoom against ~400k vertices), and coordinate precision or extent (both 4096). Tile dedup does not help either: 0 duplicate payloads for both tilers. Arc simplification was already ruled out (<1% of vertices).
- **float32 results:** freestiler stored them as 9-byte doubles. Doubles that round-trip exactly through f32 are now written as MVT floats, which is lossless (wse -2.6%).
- **The remaining +1.5% on cells is compression, not content.** Raw bytes per zoom are equal or smaller than tippecanoe's, but gzip compresses freestiler's Morton feature order slightly worse.

## Guarantees verified

- **Completeness:** 100.0% at every zoom for every freestiler run (distinct ids per zoom / source rows). tippecanoe drops 3 cells at z10 (99.997%).
- **Coincident shared edges:** unmatched directed ring edges inside the visible tile are **identical between `main` and `buffer=5` at every zoom** (3,159 / 3,198 / 3,206 / 3,189 / 3,168 / 3,102: the mesh's outer boundary). tippecanoe shows 3,046-3,441. Vertices inside the tile never move. Only repeats in the buffer zone go away.
- **Default output is byte-identical to `main`** on all four datasets. The f32 encoding was added after that check, so it changes bytes but not decoded values.
- **Bug found and fixed:** on `main`, Visvalingam-Whyatt pre-simplification reduced a nearly closed 20-vertex Bald Eagle breakline to its two end points on one pixel, and the line vanished at z8. The engine now falls back to the original line, and it is present at z8-z14.

## Arrow input with reprojection in Rust

- **Inputs accepted:** any `__arrow_c_stream__` object (pyarrow Table or RecordBatchReader, `GeoDataFrame.to_arrow()`). The geometry column can be WKB or native GeoArrow (struct or interleaved coordinates; Z ignored).
- **CRS lookup:** explicit `crs=` first (PROJJSON, a PROJ string, `EPSG:4326`, or a pyproj CRS), then the GeoArrow extension metadata, then the GeoParquet `geo` metadata. An absent `crs` key means CRS84, per the spec; `crs: null` is refused. **No CRS is refused.**
- **PROJJSON conversion:** supports TM, LCC 1SP/2SP, Albers, Mercator A/B, Web Mercator, Oblique Stereographic and LAEA. Linear units come from the CRS, so US survey feet stay feet.
- **Datums:** accepted only where PROJ's own default operation to WGS 84 is a null transformation. I checked pyproj 3.8 for WGS 84, NAD83, NAD83(NSRS2007), NAD83(2011), ETRS89, GDA94, GDA2020, NZGD2000 and SIRGAS 2000. An explicit Helmert BoundCRS also works.
- **Refused:** NAD83(HARN) and NAD83(CSRS), which PROJ shifts by about 1 m; NAD27; OSGB36; Hotine. Davis is NAD83(HARN), so it is refused and needs a fallback (see T12).
- **Accuracy against pyproj 3.8 / PROJ 9.8** (3,600-point grid over each CRS's area of use): max **73 nm** over Bald Eagle, Spring and Spring BLE (their ESRI `.prj`) and EPSG 2271, 2260 (TM), 6539, 2278, 26915, 32617, 3083, 5070, 3857, 2232 and 3424 (TM), plus a custom Texas Centric Albers in US survey feet. All 439,850 Bald Eagle mesh vertices: max **22 nm**. My first build had a 0.04% scale error on TM (`+k_0` is not read by proj4rs) and 1 m on HARN; this check caught and fixed both. Raw data: `G:\RustDev\work\T05\bench\out\crs_accuracy.json`.
- **Equivalence:** the Arrow path (source-CRS GeoParquet read with `pq.read_table`, reprojected in Rust) produces **byte-identical archives** to the GeoDataFrame path (pyproj) for cells, wse and faces. The sparse layers differ in 5 of 10,411 vertices on 3 structure lines: VW tie-breaks on sub-micrometre input differences.

## API for T12 (ras2cng viewer tiles fed as Arrow)

```python
import pyarrow.parquet as pq, pyarrow.compute as pc
from freestiler import freestile_layers, freestile_layer

table = pq.read_table(archive_parquet, columns=["geometry", "mesh_name", "cell_id"],
                      filters=[("layer", "==", "mesh_cells")])   # keeps the `geo` CRS metadata
freestile_layers(
    [("mesh_cells", table)],                 # or freestile_layer(table, min_zoom=13, crs=..., geometry_column=...)
    out_path, min_zoom=13, max_zoom=16,
    gzip_level=6, generate_ids=False, buffer=5,
)
```

- **Capability detection:** `"buffer" in inspect.signature(freestiler.freestile_layers).parameters` and `hasattr(freestiler._freestiler._LayeredTiler, "add_arrow_layer")`.
- **Sources:** a source can also be a zero-argument callable returning the table, so only one layer is held at a time. Each Arrow layer returns a report (rows, features, skipped null/empty, skipped non-scalar columns, the PROJ string used). It is printed when `quiet=False` and is available from `_LayeredTiler.add_arrow_layer`.
- **Columns:** select delivery columns with pyarrow, which replaces `_drop_internal_columns`. Struct, list and binary columns such as `bbox` are skipped automatically. Drop Z with nothing; Z/M is ignored.
- **Timestamps** are formatted by Arrow (`1999-01-01T12:00:00`). Cast to string first if the NDGeoJSON `str()` form (`1999-01-01 12:00:00`) must match.
- **Refusals:** a `ValueError` naming the datum or method (HARN, NAD27, Hotine, ...). In that case, reproject in Python (pyproj) and pass an EPSG:4326 table, which still needs no NDGeoJSON. ras2cng's `_to_wgs84` NaN-Z workaround is not needed on the Arrow path, because Z is ignored before reprojection.
- **Recommended ras2cng defaults:** `buffer=5` (tippecanoe parity; keep it at least half the widest outline stroke in tile px). Revisit the tiler preference: freestiler now matches or beats tippecanoe's size on every HEC-RAS set measured here, with no NDGeoJSON, mbtiles or `pmtiles convert` step.
- **Install:** `maturin build --release --features geoparquet,arrow` (plus `duckdb` for the file/query APIs) from `python/` on the branch. Local wheel without DuckDB: `G:\RustDev\work\T05\wheels\new\`.

## Arrow version

Arrow input and GeoParquet use **arrow-rs / parquet 59**, matching terrio (T03); commit 217d372. No code change was needed. All four Bald Eagle tilesets are byte-identical to the Arrow 57 build, the 106 Python tests pass, and the reprojection max error is unchanged at 73 nm. ## Gaps

- The default buffer is unchanged upstream-style; callers opt in.
- The 1M-cell synthetic case was not rerun.
- Arrow input goes through `LayeredTiler`, which holds one layer's features in memory, the same as the GeoDataFrame path. It is not streamed per batch into tiles.
- Unsupported projections (Hotine, polar stereographic) and datums are refused by design.
