### An addition beyond the version bump: the Pyodide backport

- **Why:** the Release dry run on the 0.5.0.1 tag concluded `failure`. `build / wheels (pyodide)` did not compile, because `python/src/tile_index.rs` called core functions compiled out on WebAssembly. 0.5.0.1 was published anyway, with no Pyodide asset.
- **Fix:** the brief says to fix a small cause, and upstream had already fixed this. PR #11's second commit (`0bd25b5`) backports upstream commits `80804f7` and `d987600`, limited to the index bindings. This tree has no palette bindings and already gates HTTP retry logging, so those parts were dropped.
- **Effect:** native code paths are unchanged. In Pyodide, index calls on paths and `DatasetIndex.write` now raise a clear error, and in-memory indexes work. The Pyodide smoke test and `docs/installation.md` were updated to match.
- **Checked by:** the Pyodide job compiled and passed its smoke test in both dry runs. It cannot be compiled on this host, which has no Emscripten.
- Only read access was used upstream.
